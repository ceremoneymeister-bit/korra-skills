# Согласованные изменения

Контроллер хранит точный текст применения, проверки, отката, последствий,
целевой Mac и их общий SHA-256. Согласие относится к этому содержимому.
Запись согласия агентом — журнал решения, не доказательство подлинности
человеческого сообщения и не замена разрешениям среды.

## Подготовить, показать, применить

До плана выясни исходные значения точечными чтениями. В apply.sh должны быть
проверка версии/модели и ожидаемого прежнего значения, остановка при расхождении,
точная цель и только согласованные действия. Для сложных операций сохраняй
резервную копию с проверкой чтения. Пустой «успешный» verify.sh не является проверкой.
Отсутствовавшую настройку отличай от настройки с явным false/0.
rollback.sh восстанавливает реальные исходные значения, проверяет текущее
состояние и не затирает более поздние изменения пользователя.

    python3 /path/mac-care/scripts/mac_care.py --session /private/session plan \
      --script /private/apply.sh --verify /private/verify.sh \
      --rollback /private/rollback.sh \
      --summary "Конкретное изменение" --impact "Последствия и способ возврата"

Покажи человеку суть и последствия простыми словами; полный текст доступен
в review-<ID>.txt. После реального выбора запиши ответ и источник сообщения:

    python3 /path/mac-care/scripts/mac_care.py --session /private/session approve \
      --plan ID --reply "Реальный ответ владельца" --source "ID сообщения или ссылка на диалог"
    python3 /path/mac-care/scripts/mac_care.py --session /private/session apply --plan ID
    python3 /path/mac-care/scripts/mac_care.py --session /private/session verify --plan ID

Не копируй пример reply как согласие. Общий запрос «посмотри» — только аудит.
Ранее данное согласие на конкретный показанный шаг можно использовать без
повторного вопроса, если содержание и последствия не изменились.

Для действия с административными правами добавь --admin-dialog при СОЗДАНИИ
плана. При применении агент вызовет стандартный диалог macOS. Человек вводит
пароль на своём Mac. Не проси пароль в чат и не сохраняй его в скрипте.
Диалог требует доступной пользовательской GUI-сессии и может быть недоступен
в конкретной SSH-среде; обработай отказ и подготовь локальный запуск только
одного уже согласованного действия. Не ослабляй системную защиту ради диалога.
При root-исполнении не используй HOME как путь домашнего каталога владельца.

Применение и откат имеют побочные эффекты. Скрипты должны быть короткими,
останавливаться при ошибке и проверять предусловия. Контроллер не анализирует
семантику произвольного shell и не гарантирует, что скрипт действительно обратим.
Удаление данных без проверенной копии не может называться обратимым; такие
действия не включать в автоматический сценарий этой версии.

## Состояния и восстановление

Повтор apply для того же плана после начала исполнения запрещён. При таймауте,
обрыве SSH, прерывании или неизвестном исходе сначала прочитай фактическое
состояние Mac. Не создавай новый план только для обхода запрета повтора.
Успешный verify подтверждает только проверки, написанные в verify.sh.
После неизвестного исхода проверь также частичные побочные эффекты и сохранность
данных. Если сценарий восстановлен, зафиксируй доказательства в отчёте.
Для согласованного отката:

    python3 /path/mac-care/scripts/mac_care.py --session /private/session rollback --plan ID

После отката отдельно проверь исходные значения и рабочий сценарий. Не запускай
verify.sh, проверяющий новое состояние, как проверку исходного состояния.
Если неизвестен исход самого отката, не повторяй его вслепую.

## Подходящие первые изменения

- Автозапуск конкретного ненужного приложения: сохранить прежнее состояние,
  использовать настройку приложения/штатный Login Items. Не удалять plist
  наугад и не сбрасывать целиком базу background items.
- Spotlight конкретного старого тома: определить VolumeUUID и точки монтирования,
  исключить текущие system/data, сохранить исходный статус. Не угадывать ОС
  по имени тома. Отключение индексации не равно удалению файла или полному
  запрету поиска; настройка может сохраняться при загрузке другой ОС.
- Настройка рабочего приложения: выяснить, какой процесс тормозит и в каком
  сценарии, сохранить только относящиеся значения. Аппаратное ускорение
  браузера/редактора не выключать по умолчанию.
- Intel с двумя GPU: исключительно после проверки модели, внешнего экрана
  и рабочих графических сценариев. Сохранить pmset отдельно для батареи/адаптера.
  Не переносить этот эксперимент на Apple Silicon или Intel с одной GPU.

Управление вентиляторами, системными службами защиты, обновление ОС,
переразметка/удаление томов и очистка пользовательских архивов не относятся
к обычному автоматическому улучшению этой версии.
