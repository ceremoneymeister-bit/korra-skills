# Одна история Telegram → локальный файл

Используйте для конкретной ссылки `https://t.me/<username>/s/<id>` или пары
`--peer` + `--id`. Работает с Python 3.10+, Telethon 1.x с модулем `stories`
(проверено на 1.44.0), Linux/macOS. В Windows нужен WSL.

Нужен **свой уже авторизованный аккаунт**, свои `api_id`/`api_hash` и существующая
SQLite-сессия Telethon. Навык не выполняет вход, не запрашивает код или пароль.
Bot API для чтения историй не подходит. Если сессии нет, сначала настройте
собственное подключение отдельно; этот скрипт новую сессию не создаёт.

## Перед запуском

Пользователь должен разрешить открыть эту историю от своего имени: просмотр
отмечается. `readStories(max_id=id)` синхронизирует прочтение всех историй автора
до указанного ID, `incrementStoryViews([id])` учитывает просмотр выбранной истории.
Автор может видеть аккаунт среди зрителей по правилам Telegram; срок хранения
списка зрителей и уже включённые настройки аккаунта влияют на отображение.
Режима скрытого просмотра у скрипта нет, настройки приватности он не меняет.
Ответ `false` на `incrementStoryViews` — допустимый Bool, а не RPC-ошибка:
официальный клиент также не требует `true`. Скрипт показывает фактический ответ,
не повторяет запрос и не обещает появление новой записи в списке зрителей.

Проверьте, что сессия не используется другим процессом или с другого IP.
Скрипт ставит локальную блокировку рядом с `.session`; сторонние клиенты должны
соблюдать ту же блокировку либо быть остановлены владельцем до запуска.
Не копируйте чужие сессии и не открывайте параллельно другой клиент.

Пять переменных из шапки задайте в защищённом окружении. JSON устройства должен
содержать непустые `device_model`, `system_version`, `app_version`, `lang_code`,
`system_lang_code`, сохранённые при настройке **этой** сессии. Не придумывайте и
не обновляйте эти значения при запуске. Если параметры неизвестны — остановитесь.
Сессию, JSON и секреты храните приватно, вне Git. Не выводите их в логи.

## Скачать

Команды выполняются из папки установленного навыка. При отсутствии зависимости
установите `Telethon>=1.43.2,<2` в своё изолированное Python-окружение.

```bash
python3 -B scripts/story.py 'https://t.me/username/s/123' --out ./stories
python3 -B scripts/story.py --peer @username --id 123 --out ./stories
```

`--peer` принимает username или известный числовой ID из кэша сессии.
По умолчанию результат лежит в `./stories/`. Скрипт печатает автора, дату UTC,
тип медиа, подпись, подтверждение запросов учёта просмотра и путь к файлу.
Не считайте файл полученным до строки «Сохранено». При ошибке после отметки
просмотра история уже может считаться прочитанной, даже если файл не скачался.

Удалённая, истёкшая или закрытая история может быть недоступна. Скрипт не обходит
доступ и не вступает в группы. Он не пишет сообщений, не ставит реакции и не
пересылает материалы. Скачанный файл используйте с учётом прав автора, затем
удалите, если хранение больше не нужно. При оборванной загрузке удалите её
частичный файл перед новым, отдельно разрешённым запуском.

## Ошибки и границы

Один запуск — одна история. Частые запросы и массовое скачивание могут привести
к FloodWait, ограничениям или блокировке аккаунта. Пауза не гарантирует защиту.
Автоматических повторов RPC и переподключений нет; при FloodWait/FROZEN или
ошибке авторизации прекратите операции и сообщите владельцу. Не пересоздавайте
сессию и не обходите ограничение сменой аккаунта или устройства. При неизвестном
исходе учёта просмотра не повторяйте запрос вслепую.

Проверка структуры или установка навыка не подтверждают доступ к конкретной
истории. Живую проверку выполняйте только на явно разрешённой истории.
