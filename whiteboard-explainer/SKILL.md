# Рисованная объяснялка

Готовый пример — ролик «Как устроен агент Korra», 92 с:
https://korra-agent.online/library/whiteboard-explainer/. Его исходник лежит
в `examples/korra-agent/`. Начинай с копии этой папки: доска, иконки, шрифт и
промпты уже согласованы между собой.

Скилл работает через терминал с Claude Code, Codex, Cursor, Hermes, OpenClaw
и Korra. Платные API и ключи не нужны. Иллюстрации делает генератор картинок,
который уже есть у агента. Рисование и кодирование идут локально на CPU.

## Сначала смысл, потом доска

1. Выясни у человека, кому ролик и что зритель должен понять. Собери 5–8
   частей: у каждой — заголовок и 2–4 элемента «иконка + подпись до трёх слов
   + пояснение до шести слов». Голоса нет, поэтому весь смысл несут подписи.
2. Сверяй каждое утверждение с источником: документацией, кодом, сайтом.
   Не обещай за продукт больше, чем там написано. Спорное убери.
3. Сюжет держит один общий план: части стоят на одной доске, и в конце камера
   отъезжает на всю схему. Последняя рамка или вывод на этом плане — главный
   момент ролика. Отдельный процесс, например «как проходит одна задача»,
   удобно рисовать полосой под основной доской.
4. Покажи человеку сценарий одной таблицей до генерации картинок.

## Иллюстрации

- Генерируй листами 3×2 из шести иконок в одном стиле. Так стиль держится
  лучше, чем при отдельных картинках. Общая часть промпта: ровный толстый
  чёрный контур маркером, плоские заливки двумя-тремя цветами бренда, белый
  фон, без теней, градиентов, текста и букв. Образцы — `examples/korra-agent/prompts/`.
- Персонажа, который повторяется, генерируй с образцом: вырежи героя из
  первого листа и передай картинкой вместе с промптом.
- Codex CLI с подпиской ChatGPT генерирует картинки встроенным инструментом:
  ```bash
  codex exec --skip-git-repo-check -C "$PWD" -s workspace-write "$(cat prompts/s1.md)" < /dev/null
  # с образцом: … "$(cat prompts/s4.md)" -i sheets/hero_ref.png < /dev/null
  ```
  Без `< /dev/null` Codex ждёт ввод и висит. `-i` принимает несколько файлов,
  поэтому картинку ставь после текста задания. Готовые файлы — в
  `~/.codex/generated_images/<сессия>/`. Другой агент использует свой
  инструмент картинок. Подойдут и свои PNG: плоские, на белом фоне.
- Положи листы в `PROJECT/sheets/`, перечисли имена ячеек в
  `PROJECT/sheets.json` и запусти `python scripts/assets.py PROJECT`. Иконки
  появятся в `assets/icons/`.
- Текст на картинках не генерируй: буквы, особенно кириллица, выходят
  искажёнными. Все подписи набираются рукописным шрифтом на доске, и движок
  пишет их по буквам. В примере — Caveat (OFL, с кириллицей).

## Доска и сборка

Формат доски — [references/board.md](references/board.md). Коротко: каждый
`.el` в `board.html` рисуется по очереди в порядке документа. Время задают
атрибуты элемента, планы камеры — блок `#timeline`.

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/playwright install chromium        # если Chromium для Playwright ещё нет
.venv/bin/python scripts/build.py PROJECT check     # кадр и снимки: нужно «ошибок: 0»
.venv/bin/python scripts/build.py PROJECT preview   # PROJECT/out/preview-*.png
.venv/bin/python scripts/build.py PROJECT render    # PROJECT/out/<output>, ~1 мин на минуту ролика
.venv/bin/python scripts/qa.py PROJECT/out/video.mp4    # листы по 32 кадра
```

Нужны Python 3.10+, ffmpeg и около 1 ГБ свободной памяти. Проверено на Linux
x86_64. На macOS и Windows нужен тот же набор, там сборка не проверялась.

## Проверка — до показа человеку

- `check` должен дать «ошибок: 0». Он ловит три вещи: элемент вылезает из
  кадра, пока рисуется; рисование начинается, когда камера ещё едет; снимок
  подписи обрезал буквы. Отдельной строкой он перечисляет уже нарисованное,
  что режет край кадра. Длинная стрелка за краем — нормально, подпись — нет.
- Посмотри `preview-*.png` целиком и оба листа `qa.py`. Ищи наложения, пустые
  кадры, подписи под рукой, мелкий текст. Размер на экране = кегль × 1920 /
  ширина окна камеры; ключевые подписи — не меньше 56 px.
- Подтверди длительность у человека. 60–90 с — потолок для ролика без голоса.

## Чего не делать

- Не давать движку фотографии, градиенты и тёмный фон: он рисует контур, а
  потом заливку кистью. Хорошо выходят только плоские картинки на белом.
- Не снимать подписи впритык к рамке блока: рукописные буквы выходят за неё.
  Скрипт уже берёт запас 0,6 кегля и останавливается, если буквы коснулись края.
- Не двигать камеру во время рисования и не ставить её на пустое место:
  переезд должен заканчиваться, когда рука начинает рисовать.
- Не публиковать ролик и не отправлять его людям без поручения.

## Устройство

Движок рисования — [whiteboard-animator](https://github.com/masihsultani/whiteboard-animator)
(MIT, PyPI 0.1.1, модель CRAFT в пакете): контур, затем заливка кистью,
текст по буквам. Каждый элемент снимается отдельно через Playwright и
получает свою карту времени. Пути SVG проявляются по длине от начала к концу.
Камера переезжает дугой с лёгким отъездом и медленно наезжает на стоянках.
Рука с маркером (`assets/hand.png`, своя кладётся в `PROJECT/assets/`)
следует за кончиком линии и масштабируется с камерой. Финальная карточка
(`data-layer="1"`) рисуется поверх белой вуали.
